# ADR 0002 観測結果を送信前にspoolへ保存する

* 状態 accepted
* 日付 2026-09-07
* 開発段階 M2

## 背景

agentは観測結果をcontrollerへ送信します。
`SPEC.md` §105・§176では、controllerに到達できない間も観測結果を保存することを求めています。
先に送信し、失敗したときだけspoolへ保存する方法では、正常時のディスク書き込みを減らせます。
ただし、送信中にagentが異常終了すると観測結果が失われます。

## 決定

観測結果は常に先にspoolへ保存します。
controllerから受領確認を受け取った後に、spoolから削除します。
読み出しだけでは削除せず、peekとacknowledgeを分けます。

## 利点と制限

送信中にagentが異常終了しても、保存済みの観測結果を再送できます。
受領確認が届く前に通信が切れた場合も再送します。
観測IDはagentが生成し、controllerが同じIDを重複挿入しないため、
再送しても記録は増えません。要件は`IMPLEMENTATION.md` §45にあります。
正常時と障害時で同じ処理を使うため、障害時だけの分岐も減らせます。

正常時もディスクへの書き込みが必要です。
WALモードのSQLiteへ1行ずつ保存し、CPU・メモリなどの使用量を`SPEC.md` §122の目標内に収めます。
書き込みの削減より、観測結果の保存を優先します。

spoolには経過時間、行数、容量の上限を設けます。
上限を超えた場合は、再送の優先順位が低い古い行から削除します。
成功した検査の記録を残すために、失敗の記録を先に削除することはありません。
要件は`IMPLEMENTATION.md` §55にあります。

## 検討した代替案

メモリ上のring bufferを定期的に保存する方式は、agentの異常終了で記録を失うため、採用しません。
agentが停止するような障害でも、停止直前の観測結果を残す必要があります。

先に送信し、失敗時だけ保存する方式も採用しません。
保存前の異常終了で記録を失うほか、正常時と障害時の処理が分かれ、
障害時の保存処理を検証する機会が少なくなるためです。
